# RQ-001 · Deepfake 检测器在跨生成器与后处理条件下的可靠性

## 0. 一句话问题（V0.1）

**当检测器遇到训练时从未见过的生成器、以及真实传播中常见的后处理（重压缩、缩放、裁剪、混剪）时，它的可靠性会下降多少，在什么条件下会失效？**

## 1. 动机与背景

- **动机**：课件 P4 把 Deepfake 检测的红色风险明确标为「未知生成器」——平时准确率 99%，攻击条件下仍可能失败。真实部署场景（内容平台审核、媒体核验、取证）里的攻击者不会只用检测器训练集里的那几个生成器。
- **现有工作**：`待补` —— 需要先建 3 张论文卡：① 该方向综述；② 跨数据集/跨生成器 benchmark；③ 一个具体的检测方法（作为基线）。
- **障碍（barriers）**：`待补` —— 从论文卡里抽出，重点找「现有方法为什么解决不了泛化」这一条。
- **为什么本方向有希望**：该方向公开数据集与开源检测器较多（课件 P32），跨生成器评测**不需要训练大模型**，单卡推理即可完成，12 周内可做出可复现结论。

## 2. 威胁模型（课件 P28 六问）

| 问题 | V0.1 的回答 |
| --- | --- |
| 攻击谁（保护对象） | Deepfake 检测系统的输出：真假标签与置信度（进而影响内容审核 / 核验决策） |
| 攻击什么阶段 | **输入阶段**（生成内容本身）；不改检测器、不做数据投毒、不碰训练流程 |
| 攻击者知道什么 | **黑盒**：不知道检测器结构与参数，也不能查询检测器（最贴近真实场景）；另设灰盒对照实验 |
| 攻击者能改什么 | ① 换用训练时未见过的生成器 / 新伪造手法；② 对生成内容做后处理：重压缩、缩放、裁剪、锐化、混剪 |
| 预算 | 离线生成无查询次数限制；算力预算限制在单卡可复现规模 |
| 成功标准 | 在 unseen 生成器 / 后处理条件下，检测指标相对 in-domain 显著下降：**AUC/准确率的绝对下降幅度**、**漏检率 FNR 的上升幅度** 达到设定阈值（具体阈值待 V0.2 依据基线复现结果确定） |

## 3. 实验设计（骨架，数字待填）

| 项目 | 内容 |
| --- | --- |
| 数据集 | 候选：FaceForensics++ / Celeb-DF / DFDC / DF40（**待核实**，用前建论文卡或来源记录） |
| 基线 | 候选：1–2 个公开检测器（Xception / EfficientNet / CLIP 类骨干） |
| 指标 | ① clean 与 attack 条件**分开报告**；② 跨生成器：AUC、FNR、FPR；③ 后处理：指标随压缩率/分辨率的衰减曲线 |
| 自变量 | 生成器族（见过 / 未见）× 后处理类型与强度 |
| 对照 | ① in-domain 测试结果（性能上界参照）；② 简单 sanity baseline（例如频域特征 + 线性分类器） |
| 预期结果 | 跨生成器条件下显著下降，且不同后处理的衰减幅度差异明显（具体幅度**待实测**，不预设） |

## 4. 可实施性五问（课件 P36）

| 问题 | 回答 |
| --- | --- |
| 保护什么？ | 内容真实性判断（真假标签与置信度） |
| 谁攻击？ | 使用新生成器 / 后处理造假的攻击者 |
| 能做什么？ | 黑盒：换生成器 + 做后处理，不能改检测器 |
| 怎么算成功？ | 指标衰减达到阈值；并排序出最脆弱的 (生成器 × 后处理) 组合 |
| 怎么实验？ | 公开数据 + 开源基线 + 单卡推理，指标可复现 |
