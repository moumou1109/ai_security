## 2. 卡片体系

| 卡片 | 回答的问题 | 什么时候建 | 命名规范 |
| --- | --- | --- | --- |
| 方向卡 | 我要研究的大方向是什么？边界在哪？ | 定方向时，一般 1 张 | `方向卡-<方向>.md` |
| 关键词卡 | 这个领域的术语、检索式是什么？ | 开始检索前 | `关键词卡-<术语>.md` |
| 论文卡 | 这篇论文做了什么，能被我用来做什么？ | 每读一篇论文 | `论文卡-<一作+年份>-<短标题>.md` |
| 证据卡 | 哪一句结论 / 哪张图 / 哪个数字能支撑我的论点？ | 读论文、跑实验时随手抽 | `证据卡-<来源简称>-<两位编号>.md` |
| 研究问题卡（RQ） | 我到底要验证什么？怎么算成功？ | 一个问题一张，持续升版本 | `RQ-<三位编号>-<短标题>.md` |
| 概念卡 | 这个概念到底是什么意思？ | 遇到不懂的术语 | `概念卡-<术语>.md` |
| 实验卡 | 我做了什么、结果如何、失败在哪？ | 每次跑实验 | `实验卡-EXP-<三位编号>-<短标题>.md` |
| 来源记录 | 这条信息是从哪来的？可信吗？ | 拿到课件 / 网页 / 数据集 / 代码时 | `来源-<三位编号>-<名称>.md` |

每张卡片都用统一的 YAML frontmatter（`类型`、`状态`、`更新日期`、`标签` 等），这样以后要换成 Dataview / Bases 自动汇总时不用返工。

## 3. 卡片怎么连成一条链（研究工作流）

课件 P41 的逻辑：**没有真实材料，就没有论文自动化**。所以本库的流程是单向收敛的：

```
论文 / 网页 / 代码
      ↓ 读
   论文卡  ←→  概念卡（看不懂的概念单独记）
      ↓ 抽
   证据卡（可引用的结论、数据、图表）
      ↓ 支持 / 反驳
   研究问题卡 RQ（V0.1 → V0.2 → …）
      ↓ 需要验证
   实验卡（含失败实验）
      ↓ 汇总
   论文草稿 / 汇报 PPT
```

配套的三条硬规则：

1. **无来源不下结论**：没找到出处的先写成 `待核实`，不要写成事实。
2. **一卡一主题**：卡片太长就拆，卡片之间用 `[[双链]]` 连起来，避免孤岛。
3. **AI 生成的内容要标注**：哪一段是 AI 帮忙整理、谁 verify 的，写清楚（课件 P8–P9：过程要留痕）。

## 4. 小组协作与 Git 规范

### 4.1 首次接入（协作者）

```bash
git clone https://github.com/moumou1109/ai_security.git
```

然后用 Obsidian「打开文件夹作为仓库」选择克隆下来的目录，第一次打开时选择 **信任作者并启用社区插件**（插件文件已随仓库提供）。
推送时用 GitHub 账号登录一次即可（Git Credential Manager 会记住）。

### 4.2 邀请协作者（组长在 GitHub 网页操作）

仓库 → `Settings` → `Collaborators` → `Add people` → 输入对方 GitHub 用户名 → 对方接受邀请。

### 4.3 分支策略

| 分支 | 用途 |
| --- | --- |
| `main` | 只放整理好的、双方都认的卡片 |
| `feat/<姓名>-<主题>` | 个人在写的新卡片（例如 `feat/moumou-deepfake-baseline`） |

大改动走 Pull Request，由另一名成员看一眼再合并；小改动（新增自己的卡片）可以直接提交到 `main`。

### 4.4 日常动作

```bash
git pull            # 开始工作前先拉
git add -A
git commit -m "卡片(论文): 新增 XXX 论文卡"
git push
```

提交信息约定：`卡片(方向|关键词|论文|证据|RQ|概念|实验|来源): 做了什么`、`实验: EXP-001 …`、`chore: 配置/插件调整`。

### 4.5 怎么少打架（协作防冲突）

- **各写各的卡片文件**：冲突 90% 来自两个人同时改同一个文件。
- **共享卡片先沟通**：`00-首页.md`、方向卡、RQ 卡属于共享文件，改之前在小群里说一声。
- 不建议开多个工作副本同步同一张卡；Obsidian Git 插件的自动 commit/push 建议间隔 ≥ 30 分钟。
- `.obsidian/workspace.json` 和插件的 `data.json` 已在 `.gitignore` 里，不会被提交，也不会互相覆盖界面。
